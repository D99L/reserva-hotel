# Definition of Done (DOD) para las vistas

Aca estan los criterios de aceptacion para las vistas (frontend) desarrolladas en esta etapa.

| ID | Criterio de Aceptacion | Descripcion | Como validarlo | Estado |
|---|---|---|---|---|
| DOD-1 | Responsivo | Las vistas se deben ver bien en celular y pc. | Cambiar el tamaño de la ventana o usar devtools. | Cumple |
| DOD-2 | Navegacion | Los botones deben llevar a la pantalla correcta sin dar error. | Hacer click en todo el flujo de reserva. | Cumple |
| DOD-3 | Estilos | Se deben usar los colores del hotel y estar ordenado. | Revision visual del diseño. | Cumple |
| DOD-4 | Accesibilidad | Buen contraste de colores y textos claros para el usuario. | Chequear contraste y tamaños de letra. | Cumple |
| DOD-5 | Feedback | Mostrar si la reserva funciono o si hay error al llenar datos. | Probar el formulario. | Cumple |
| DOD-6 | Datos correctos | Lo que se muestra en las vistas debe calzar con la base de datos SQL (ej: precio, tipo habitacion). | Revisar los campos. | Cumple |
| DOD-7 | Repositorio | El avance debe estar en Git con sus commits. | Ver el log de github. | Cumple |
| DOD-8 | Trello | Adjuntar las imagenes de las vistas en trello y pasarlo a "Hecho". | Ver el tablero Kanban. | Cumple |
